# PHP2Shell記事の図版レビューと修正

対象: [php2shell-explained.md](../../../articles/php2shell-explained.md)

## 判断基準

文章を枠に入れるだけなら、Markdownの本文・表・Mermaidを使う。画像は、物の位置関係や、同じ物の変化を見せることで理解が進む箇所に使う。

## 6枚の見直し

| 対象 | 元の図の問題 | 記事への反映 |
|---|---|---|
| 01 公開までの段取り | 手順と日付が同じ大きさのカードに並び、対応関係が曖昧。後の時系列表とも重複していた | 通常の手順は縦向きのMermaid。今回の出来事は既存の日付表で読む |
| 02 PHPのどの層か | 「上・中・下」と文章で説明しており、ブラウザーやサーバーとの位置関係が見えなかった | ブラウザーをサーバーの外に配置。サーバー内を立体的な3層にし、PHP本体を強調 |
| 04 作りかけの情報 | 中断後も何が不完全なのかが見えず、説明文の言い換えだった | 同じ管理票の空欄が3コマを通して残る生成イラスト。最後に空欄を拡大して示す |
| 06 古い参照 | データと参照を別々に描いておらず、何が消え、何が残るか分からなかった | 同じトレーA・同じメモ・同じ担当者を維持。紫の書類だけが取り除かれ、別のオレンジの書類へ変わる生成イラスト |
| 07 きっかけと乗っ取り | 一本道の矢印が、不具合の発生からコード実行へ自動的に進むように見えた | 異常終了などの経路と、条件と制御が必要なコード実行の経路に分岐するMermaid |
| 08 立場ごとの対応 | 行動の比較を画像にしており、本文の再掲になっていた | 「使う人」「サイトを公開する人」「サーバーを管理する人」のMarkdown表 |

03・05の挿絵は、04・06と同じ説明を繰り返すため記事の参照から外した。画像は9枚から4枚になった。01・03・05・07・08の旧PNGは現在の記事では参照していない。

## 内容の確認

図の説明を以下の一次資料と照合した。

- [PHP公式アドバイザリ：OOM corruption](https://github.com/php/php-src/security/advisories/GHSA-w8hw-w9fx-j79w)
- [PHP公式アドバイザリ：stale global state](https://github.com/php/php-src/security/advisories/GHSA-6wmf-4rv5-p3rp)
- [PHP Foundation：公開変更の経緯](https://thephp.foundation/blog/2026/10/21/todays-php-security-release-and-how-were-strengthening-php-security/)

02は依存関係の模式図。04・06は作業机の比喩であり、実際のメモリ構造ではない。06の別の書類は、解放された場所が再利用された場合を表す。コード実行の成立条件や攻撃成功率を絵の距離・段差で表現しない。

## 表示確認

2026-10-23に、Zenn用Markdown変換・CSSを使うローカルプレビューで確認。

- 使用パッケージ: `zenn-markdown-html@0.5.2`、`zenn-content-css@0.5.8`、`mermaid@11.17.2`。
- デスクトップ: ビューポート1080px、本文・図版720px、冒頭の挿絵480px。
- スマートフォン: ビューポート375px、本文・図版335px。
- 画像4枚の読み込み、Mermaid2件の描画、ページ全体の横はみ出しがないことを確認。
- 縮小表示を目視し、02を縦構図へ変更、01を縦のフローへ変更、07のラベルを短くした。
- 04の空欄、06の古いメモと書類の違い、同じ担当者の括弧を目視確認。
- 08の表もスマートフォン幅で折り返しを確認。
- 記事中の画像URLがローカルファイルへ対応すること、`git diff --check` を確認。

プレビューHTML・スクリーンショット・寸法レポートは、リポジトリで除外されている `docs/php2shell-figures-review/` に保存する。
